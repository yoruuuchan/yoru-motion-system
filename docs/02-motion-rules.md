# 02 · 结构与动效规则

> 所有数字都来自本地研究用渲染参考集的**逐帧测量**，不是目测，也不是套用常见做法。参考视频本身不随仓库分发。
> 测量脚本和过程见本文末尾「怎么量的」。素材统一为 90 帧 / 30fps / 3.00 秒 / 960×540。

---

## 零、一条压倒性的规则：布局不重排

这是整套素材里最重要、也最容易被忽略的一条。

**每个模板在第 0 帧就已经把最终布局排好了。元素只在自己的最终位置上改 opacity 和 transform，永远不会因为新元素加入而挤动别人。**

三处独立验证：

| 素材 | 验证方式 | 结果 |
|---|---|---|
| `staggered-words` | 追踪第一个词 "Design." 的 x 坐标 | 全程不动；第 1 个词出现时就已经站在三个词都排完之后的位置 |
| `patient-journey` | 追踪第 1 个节点圆心 x | 从 f11 到 f89 完全不动，尽管后面还有 3 个节点陆续加入 |
| `changelog` | 观察分隔线 | 内容还没出现时，分隔线已经画好了——骨架先于内容 |

**为什么重要**：如果用"逐个 append 到 DOM"的写法，每加一个元素整行都会重排，视觉上是所有已出现元素一起抖一下。三秒的片子里这种抖动非常显眼。

**系统里怎么落实的**：`Typewriter` 会把完整字符串以 `visibility: hidden` 垫在下面占位；`StaggeredWords` 用 flex 一次排完所有词再逐个淡入；所有 stagger 都是"元素已在位、只改透明度"。

## 一、时间常量

`src/core/timing.ts` 里的每个数字都对应下面一条测量。

| 常量 | 值 | 来源 |
|---|---:|---|
| `TIMING.fade` | 8 帧 | `concept-breakdown` 标题亮度 f2=72 → f8=255（0-255），8 帧走完 |
| `TIMING.rise` | 24 设计 px | 同上，文字块质心从 +6.3px 升到 0（480px 高的帧上量，换算到 1080p ≈ 25px） |
| `TIMING.stagger` | 8 帧 | `bar-chart-reveal` 四根柱起始帧 **11 / 19 / 27 / 35**——固定 8 帧，不是比例也不是缓动 |
| `TIMING.phase` | 18 帧 | `before-after` 左卡 f6 出现、右卡 f24 出现 |
| `TIMING.counter` | 24 帧 | `day-summary` 数字 0(f6) → 1(f11) → 19(f17) → 23(f24) |
| `TIMING.draw` | 10 帧 | `step-explainer` 下划线自左向右扫完约 10 帧 |
| `TIMING.hold` | 26 帧 | 见第五节"动作要提前结束" |

不同模板会覆盖这些默认值，覆盖的地方都在模板注释里写了实测帧号。典型偏差：

- 读文字的结构 stagger 更慢：`concept-breakdown` 11 帧、`step-explainer` 14 帧、`feature-showcase` 14 帧
- 看小方块的结构 stagger 更快：`staggered-words` 6 帧、`countdown-timer` 6 帧、`bento-grid` 7 帧

**规律**：一个元素要读的字越多，它需要的呼吸就越长。8 帧是数据类的默认值，不是全局真理。

## 二、Spring：一个可以直接抄的数字

`bar-chart-reveal` 第 1 根柱的逐帧高度（像素，480×270 采样）：

```
f11  f12  f13  f14  f15  f16  f17  f18  f19  f20  f21  f22 ... f28  f29  f30 ... 稳态
 5   15   27   38   48   56   61   64   66   66   65   63      58   58   59      59
```

读出三件事：

1. **最高点 66，稳态 59 → 过冲 11.9%**
2. **f28-29 回落到 58 → 有 1px 的反向摆动**，说明它是真正的欠阻尼弹簧，不是 back-ease 那种"冲过去再回来就完事"
3. 第一个峰在起跳后约 9 帧

用阻尼振子拟合，逐帧对比平均绝对误差：

| 配置 | 平均误差 | 过冲 |
|---|---:|---:|
| Remotion 默认 `{stiffness:100, damping:10}` | **5.67%** | 16.3% |
| `{stiffness:120, damping:12}` | 3.09% | 12.7% |
| **`{stiffness:150, damping:14}`** | **0.70%** | **11.1%** |
| `{stiffness:160, damping:15}` | 0.97% | 9.8% |

系统取 `SPRING.pop = {stiffness: 150, damping: 14, mass: 1}`。Remotion 默认值误差大 5 倍，弹得明显更夸张——不是错，但不是你筛出来的那种感觉。

大面板（模态框、浏览器窗口）用 `SPRING.surface = {stiffness: 190, damping: 22}`，几乎不过冲。因为一个占半屏的东西弹一下，观感上是整个画面在晃。

## 三、文字不回弹，实体才回弹

`concept-breakdown` 标题的质心位移：

```
f2    f3    f4    f5    f6    f7    f8
+6.29 +5.43 +4.42 +2.65 +1.48 +0.46  0.00
```

单调收敛，**没有越过 0**。同一批素材里柱子过冲 11.9%，文字过冲 0%。

**规则**：
- 文字 → `FadeRise`（8 帧淡入 + 24px 上移 + `cubic-bezier(0.16, 1, 0.3, 1)`）
- 实体（柱、卡、chip、徽章）→ `SpringIn` / `GrowBar`（`SPRING.pop`）

## 四、数值标签跟着实体跑

`bar-chart-reveal` 里 "65%" 的行位置对比柱顶：

| 帧 | 柱顶 y | 标签 y |
|---|---:|---:|
| f15 | 148 | 137-139 |
| f17 | 135 | 124-129 |
| f20 | 130（过冲最高点） | 120-124 |
| f25 | 137 | 126-130 |
| 稳态 | 137 | 126-131 |

标签和柱顶之间的距离恒定，**标签跟着柱子一起过冲、一起回落**。它不是等在最终位置上淡入的。

所以 `GrowBar` 有一个 `cap` 插槽，渲染在生长边上，用 flex 的 `justify-content: flex-end` 让它被顶上去。这比"算出柱高再定位标签"更省事，也天然正确。

## 五、动作要提前结束

对 20 个代表性模板逐帧算相邻帧差（画面变化量），得到每条片子最后一次可见运动的帧号（总长 90）：

| 结束帧 | 模板 |
|---|---|
| f32-35 | `app-feature-callout`、`portfolio-breakdown`、`product-reveal` |
| f51-57 | `bar-chart-reveal`、`before-after`、`changelog`、`bento-grid`、`feature-showcase`、`screen-showcase` |
| f60-66 | `day-summary`、`social-post`、`step-explainer`、`concept-breakdown`、`payment-flow` |
| f71-82 | `typewriter-reveal`、`patient-journey`、`countdown-timer`、`appointment-booking` |

**多数模板在 40%-70% 处就停了，剩下 1-2 秒是静帧。** 静帧不是没剪干净，是留给人读完的时间。

例外只有两个，且都合理：`countdown-timer` 的跑动数字本身就是内容；`appointment-booking` 的按钮故意最后到。

系统里的落实：每个模板导出一个 `xxxDuration(props)`，算法是 `最后一拍 + settle + hold`，`hold` 默认 26 帧。加元素会自动加长，不用手改时长。

## 六、二次动作：一个元素可以有两拍

`day-summary` 的清单行：

| 行 | 完全显形 | 方块填充 | 间隔 |
|---|---:|---:|---:|
| 1 | 31 | 34 | 3 |
| 2 | 37 | 41 | 4 |
| 3 | 44 | 48 | 4 |
| 4 | 51 | 55 | 4 |

行之间是 7 帧一步；每一行**完全显形之后 3-4 帧**方块才被填上、文字才加删除线（从该行开始淡入算起约 11 帧）。同样的两拍结构出现在：

- `appointment-booking`：选项行 f45 出现 → 同一行在稍后亮起选中态
- `modal-explainer`：卡片先到位 → 内部内容再翻页

**这是"组装完成"和"有人在用"之间的差别。** 一次性出现的界面是截图，出现后又发生变化的界面才像有人在操作。

系统里：`MetricCounter` 的 `ROW_STEP = 7` / `CHECK_OFFSET = 11`，`UiFlow` 的选中态延迟 6 帧。

## 七、相位：两个块之间的 18 帧

`before-after` 的完整时间轴：

```
f6   左卡（空框）出现
f11  左侧第 1 行
f17  左侧第 2 行
f24  左侧第 3 行 + 箭头 + 右卡（空框）
f33  右侧第 1 行
f45  右侧第 2 行
```

左块起点 f6、右块起点 f24，相差 18 帧 = 0.6 秒。

**如果两块同时出现，它读起来是一张双栏表格；错开 18 帧，它读起来是"从这个变成那个"。** 相位差本身就是语义。

`screen-showcase` 用了同样的手法：窗口 f2 起，右侧功能列表 f24 起。先给你看东西，再说关于它的话。

## 八、typography 行为

| 角色 | 行为 |
|---|---|
| 标题 | 整块淡入 + 上移，不逐字 |
| 逐词（`staggered-words`） | 6 帧一个词，整行提前排好版 |
| 逐字（`typewriter-reveal`） | **4.3 帧/字符 ≈ 7 字符/秒**（f6 时 1 字符，f88 时 20 字符），光标持续闪烁，字体必须等宽 |
| 正文段落（`social-post`） | 整段淡入，不逐词——引用是拿来读的 |
| eyebrow 小标签 | 和标题同时或早 2 帧，永远不单独成一拍 |

**等宽不是装饰**：比例字体下每个新字符的宽度不同，光标会横向抖动。`TypewriterLine` 无视 skin 强制使用 mono 就是为了这个。

**中文的额外问题**（原素材全英文，这条是我们自己的）：7 字符/秒对中文太快，一个汉字的信息量约等于 2-3 个字母。中文文案建议 `cps` 调到 4-5。

## 九、颜色规则

1. **数据是明度阶，不是色相。** 41 个 keep 里没有一个用彩色区分序列。浅底 `#D4D4D8 → #A1A1AA → #52525B → #18181B`，深底反过来。
2. **强调色只用在"状态"上**：选中的行、AFTER 那一侧、主按钮。不用来编码数据。
3. **最浅那一阶必须能从背景里看出来。** 第一版 `yoru-light` 的 `ramp[0]` 是 `#D6DFE1`，背景是 `#F2F5F5`——渲染出来图例几乎看不见，已改成 `#B9C7CC`。这类问题只有真的渲染出来才会发现，Studio 里盯着看不一定注意得到。
4. 唯一的语义色是 `before-after` 里的红 ✗ 和绿 ✓。

## 十、图片 / 视频占位

原素材里所有"图片"都是灰色骨架块——它们从来没有放过真实照片。所以关于真实素材的规则是我们自己定的，也必须标记为未经你验收：

- 所有媒体位走同一个 `Placeholder` 组件
- 没有 `src` 时渲染主题化的骨架块（不画图标、不写"图片缺失"）
- **有没有 `src`，这个槽位的尺寸完全一样**——换成真图不会推动画面上任何其他东西
- `.mp4/.mov/.webm/.mkv` 走 `OffthreadVideo`，其余走 `Img`

`MaskedReveal`（遮罩擦除）同理：原素材里**没有出现过**任何遮罩动效，只有淡入和弹簧。它作为扩展提供，但在你真正验收之前不应该当成"符合你口味"的东西用。

## 十一、9:16 适配

原素材全部是 16:9，**没有任何竖屏证据**。这一层完全是我们自己的规则，需要你验收。

采用的做法：**按格式换算单位，然后重新排版**，不是缩放。

```
u = 帧宽 / (16:9 ? 1920 : 1080)
```

同一个"88 设计 px"的标题，在 16:9 上占帧宽 4.6%，在 9:16 上占 8.1%。竖屏的字本来就该更大。

真正重排（不是换个方向摆）的模板：

| 模板 | 16:9 | 9:16 |
|---|---|---|
| `BarChartReveal` | 竖柱 + 底部类目 | **横条** + 类目移到条上方 |
| `BeforeAfter` | 左右并排 + `→` | 上下堆叠 + `↓` |
| `StepTimeline` | 横向轨道 + 虚线 | 纵向轨道 + 竖虚线 |
| `ScreenShowcase` | 窗口左 / 列表右 | 窗口上 / 列表下 |
| `DonutBreakdown` | 环左 / 图例右 | 环上 / 图例下 |
| `FeatureTrio` | 三卡横排 | 三卡竖排 |
| `UiCallout` | 标注从右缘滑出 | 标注从下缘滑出 |

字号下限对齐 Remotion 官方的 video-layout 建议（1080 宽画布：主标题 ≥84px、重要辅助文字 ≥44px）：`title` 88、`subtitle` 54、`body` 44。第一版用的 38/24 在竖屏上偏小，已经调过。

**已知未解决**：竖屏下卡片类模板（`ChangelogCard`、`UiFlow`、`MetricCounter`）在画面上下会留出较大空白。这在"卡片浮在背景上"的用法里是对的，但如果要做满屏竖版还需要另一套竖屏专属布局。等你看过再决定。

## 十二、怎么量的

研究过程使用普通逐帧抽取与图像测量：

```bash
# 示例：先把参考视频统一缩放并抽成逐帧图片
ffmpeg -i reference.mp4 -vf scale=480:270 -q:v 3 frames/f_%03d.jpg

# 再用 Python + Pillow / numpy 做测量：
# - 柱高：找目标列区间内的边界
# - 淡入：追踪文字包围盒亮度峰值和质心
# - 节奏：比较相邻帧差，定位每一拍起点
```

拟合弹簧用的是标准欠阻尼阶跃响应：

```
x(t) = 1 - e^(-ζω₀t)·(cos(ω_d·t) + (ζω₀/ω_d)·sin(ω_d·t))
ω₀ = √(k/m),  ζ = c/(2√(km)),  ω_d = ω₀√(1-ζ²)
```

把 `{stiffness, damping}` 网格搜一遍，取和实测高度序列平均绝对误差最小的一组。
